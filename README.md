# Instagram DM Auto-Reply Bot (n8n)

Self-hosted n8n system that answers Instagram DMs for a small shop with an LLM and a shop knowledge file, and hands conversations to a human when needed. The brief is `../instagram-dm-bot-plan.md`; this README is the setup and operations runbook.

Status: workflows, prompt, scripts and fixtures are built and were tested on a local n8n 2.43.8 against mock Instagram/Anthropic/Telegram servers (see "What was tested"). **Nothing has been tested against real Meta, a real LLM or a real Telegram bot yet**, and nothing is deployed. Phases 0, 1 (server), 2 (Meta) and 7 to 8 need Ali.

## Contents

```
.env.example            all settings (copy to .env)
docker-compose.yml      n8n + Caddy
Caddyfile               HTTPS for n8n.<domain>
knowledge/shop.md       shop facts, Ali edits this          (empty template)
prompts/system.md       system prompt + canned messages     (edit shop name, review fi/fa text)
workflows/*.json        WF1 reply, WF2 token refresh, WF3 error alert, WF4 retention, WF5 admin dashboard
docs/DEPLOY.md          start here: server, domain, Instagram connection, go-live, daily use
fixtures/*.json         sample webhook payloads (synthetic, see "Fixtures")
scripts/                subscribe.sh, send-fixture.sh, refresh-token.sh
docs/meta-setup.md      click-by-click Meta/Instagram setup (MANUAL)
tools/                  generator for workflows/*.json and a mock server for tests
```

`workflows/*.json` are generated by `node tools/build-workflows.js`. Edit in the n8n editor and re-export, or edit `tools/` and regenerate; do not do both without checking the diff.

## First-time setup

### Phase 0: Ali fills in the shop facts (MANUAL)

1. Answer the open questions in plan section 13.
2. Fill `knowledge/shop.md` (hours, address, products with prices, delivery, returns, FAQ, and the "Always hand off" list).
3. In `prompts/system.md`, inside the `CANNED MESSAGES` JSON block, set `shop_name` (and optionally `bot_name`). Have a native speaker check the Finnish and Persian lines. The supported languages are English, Finnish and Persian; that is an assumption, change the list in the prompt (rule 6) and the canned block if the shop needs others.

### Phase 1: server

1. EU VPS with Docker. Point DNS `n8n.<domain>` at it (MANUAL, Ali).
2. `cp .env.example .env` and fill it in. Generate `N8N_ENCRYPTION_KEY` with `openssl rand -hex 32`. Set `IG_VERIFY_TOKEN` with `openssl rand -hex 16`. Leave `BOT_MODE=shadow`.
3. `docker compose up -d`. Open `https://n8n.<domain>`, create the owner account with a strong password (anyone with editor access can read the Instagram token).
4. Check the running version: `docker compose exec n8n n8n --version`. The workflows were built on 2.43.8. `docker-compose.yml` uses `:latest`; pin it to a version you have tested.

Done when `https://n8n.<domain>` loads with a valid certificate.

### Create the Data Tables (once)

n8n UI: **Data tables > Create**. Create exactly these four tables and columns. Column names and types matter.

| Table | Columns (type) |
|---|---|
| `igdm_processed_messages` | `mid` (string), `received_at` (date) |
| `igdm_conversations` | `igsid` (string), `status` (string), `paused_until` (date), `last_customer_msg_at` (date), `disclosed` (boolean), `language` (string), `updated_at` (date) |
| `igdm_messages` | `igsid` (string), `direction` (string), `sender` (string), `text` (string), `mid` (string), `created_at` (date) |
| `igdm_config` | `key` (string), `value` (string), `updated_at` (date) |

Do not add an `id` column; n8n adds it. The `igdm_` prefix is deliberate, see "Deviations from the plan".

### Import and activate the workflows

```
docker compose exec n8n n8n import:workflow --separate --input=/data/workflows
for id in igdmWf3ErrorAlert igdmWf1Webhook01 igdmWf2TokenRefr1 igdmWf4Retention01 igdmWf5Admin01; do
  docker compose exec n8n n8n publish:workflow --id=$id
done
docker compose restart n8n
```

On older n8n versions use `n8n update:workflow --id=<id> --active=true` instead of `publish:workflow`. Alternatively open each workflow in the editor and use the Publish/Active toggle.

**All four must be active, including WF3.** n8n refuses to run an inactive error workflow ("Workflow ... is not active and cannot be executed"). The workflows keep fixed IDs, and WF1, WF2 and WF4 already name WF3 as their error workflow (Settings > Error workflow). Check both in the editor after import.

Confirm each workflow opens in the editor without errors. (The import itself and execution of every node were checked on the test instance; opening the UI could not be checked from the command line.)

### Phases 2 and 3: connect Meta (MANUAL) and prove signatures

Follow `docs/meta-setup.md`. Key points:

- WF1 must be active before Meta can verify the callback URL `https://n8n.<domain>/webhook/ig`.
- Put the Instagram token in `igdm_config` (key `ig_access_token`, plus `ig_token_expires_at`).
- Phase 3 signature secret: set both candidate secrets (`IG_APP_SECRET`, `IG_APP_SECRET_ALT`), send one real DM, read the `matched` field in the **Verify Signature** node output (`primary` or `alt`). Keep the matching one in `IG_APP_SECRET` and empty `IG_APP_SECRET_ALT`.
- If DMs from accounts with no role on the app do not trigger WF1 in Live mode, you need Phase 2b (Business Verification and App Review).
- Save a real captured payload into `fixtures/` (the shipped fixtures are synthetic).

## Operating it

- **Admin dashboard** (WF5): `https://n8n.<domain>/webhook/admin?key=<ADMIN_KEY>`. Switch On / Practice / Off (stored in `igdm_config` row `bot_mode`, overrides `BOT_MODE`), see who needs a human, hand chats back, edit `shop.md`. Walkthrough in `docs/DEPLOY.md`.
- **Shadow mode** (`BOT_MODE=shadow`, the default start mode): nothing is sent to customers. Each draft and each handoff arrives on Telegram, prefixed `[SHADOW]`. Review for about a week, fix `knowledge/shop.md` and `prompts/system.md`, and move to auto after two days with no wrong drafts.
- **Auto mode**: press **On** in the dashboard (or set `BOT_MODE=auto` in `.env` for the starting mode).
- **Changing knowledge/prompt**: edit the file on the server; it is read on every message, no restart needed.
- **Handoff**: the bot sets the conversation to `human` for `OWNER_PAUSE_HOURS`, and Telegram tells Ali why. Ali answers in the Instagram app.
- **Owner takeover**: when Ali replies from the Instagram app, WF1 sees the echo, finds no bot-sent message with that id, and pauses the bot for that customer for `OWNER_PAUSE_HOURS`. WF4 sets `status` back to `bot` once the pause has passed.
- **Token**: WF2 refreshes weekly and warns on Telegram when fewer than 7 days remain. Manual refresh: `scripts/refresh-token.sh <token>`, then update `igdm_config`. A fully expired token cannot be refreshed; generate a new one (docs/meta-setup.md step 5). WF1 alerts immediately when Instagram answers with OAuth error 190.
- **Backups**: copy the `n8n_data` directory daily. Export workflows after every change: `docker compose exec n8n n8n export:workflow --all --separate --output=/data/workflows` (the mount is read-only in `docker-compose.yml`; export to `/home/node/.n8n` and copy out, or remove `:ro` while exporting).
- **Uptime check**: an external monitor on `https://n8n.<domain>/healthz`.
- **Privacy**: say in the shop's privacy policy that an automated system and an AI provider (Anthropic) process messages; check the provider's data processing terms. Messages are kept `RETENTION_DAYS` (30) days. Card numbers in a DM are replaced by `[card number removed]` before anything is stored, sent to the LLM or alerted.

## Deviations from the plan, and things to know

- **Table names are prefixed `igdm_`.** n8n's Data Table node looks up a table "by name" with a substring match and takes the first hit, so `messages` can resolve to `processed_messages` (this broke the first test run). Prefixed names cannot collide with each other or with other tables on the instance. Logical names in the plan map one-to-one.
- **Graph API version is `v26.0`** (the plan said `v25.0`, VERIFY). Meta's docs on 2026-10-19 use `v26.0` in all messaging examples.
- **Message limit is 1000 UTF-8 bytes**, not characters (Meta docs). Persian text uses two bytes per character, so replies are split by bytes.
- **LLM output uses a forced tool call** (`reply_to_customer`) instead of free JSON, which makes the section 7.2 contract reliable. The reply is validated; one retry, then handoff.
- **Card numbers** are detected in code (digit runs that pass the Luhn check) and never reach the LLM, the database or Telegram. The plan only asked the prompt to handle this.
- **"Asks for a person" shortcut** applies to messages of 80 characters or fewer, matched as whole words from `human_keywords` in `prompts/system.md`. Longer messages go to the LLM, whose rules cover the same case. This avoids handing off "is your human hair wig in stock, and how much is it".
- **24-hour guard** is applied at the start (a message whose timestamp is older than 24 h is dropped before any LLM cost) and nothing is sent in that case, no alert either.
- **Email fallback for WF3** is not included. It needs SMTP credentials, which cannot be shipped in a workflow file. Add an Email Send node after the Telegram node if wanted.
- **Telegram bot token appears in the request URL**, which n8n stores in execution data. Treat execution data as sensitive, and consider `EXECUTIONS_DATA_PRUNE` settings.
- Optional env vars `ANTHROPIC_API_BASE`, `TELEGRAM_API_BASE` and `IG_APP_SECRET_ALT` were added to `.env.example` (tests and Phase 3). Leave the first two empty in production.
- `NODE_FUNCTION_ALLOW_BUILTIN=crypto` is required for the signature check.
- Concurrency is per conversation by design: with `DEBOUNCE_SECONDS`, every message in a burst starts its own execution, and only the newest one answers.
- The Data Table node and file-access restriction behaviours above are specific to the tested n8n version; re-run the fixtures after any n8n upgrade.

## Troubleshooting

| Symptom | Likely cause |
|---|---|
| Meta cannot verify the callback | WF1 not active, `IG_VERIFY_TOKEN` differs from the dashboard value, or the Caddy/DNS setup is wrong |
| Execution ends right after `Verify Signature` | Wrong secret. Check the log line `signature check FAILED`; do the Phase 3 comparison |
| "Access to the file is not allowed" | `N8N_RESTRICT_FILE_ACCESS_TO` does not include `/data/knowledge;/data/prompts`, or the mounts are missing |
| "Cannot find module 'crypto'" in a Code node | `NODE_FUNCTION_ALLOW_BUILTIN=crypto` missing |
| `$env` access denied | `N8N_BLOCK_ENV_ACCESS_IN_NODE=false` missing |
| Error alert never arrives although a workflow failed | WF3 not active, or the workflow's Error workflow setting is empty |
| "Data table with name ... not found" | Table missing or misspelled; see the table list above |
| Bot silent for one customer | Their conversation has `status = human` and `paused_until` in the future; edit the row or wait |
